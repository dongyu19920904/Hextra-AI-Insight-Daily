### 1. [AI 時代のコードレビュー：2 回書く方が実は速い](https://baoyu.io/blog/ai-era-code-review-write-twice-faster)

昔、コード作成で一番つらかったことは？1 版目は動いたのに、要件の理解が半分間違ってて、アーキテクチャが反復に耐えられず、書き直したいのに上司が許さない。3 年後に振り返ると、そのコードは誰も触れない糞コードになってた。

今は AI がコード作成を超高速化、3 日分の作業が 3 時間で動く版が出てくる。だから「プロトタイプ開発法」が理論から実践へ：**1 版目は AI に思いっきり書かせる、アーキテクチャなんて気にしない品質も気にしない、とにかくバグを踏み尽くす；2 版目は従来のエンジニアリングに戻る、ちゃんと設計してちゃんと review。** 1 版目は捨てるものと認める方が、むしろ 2 版目がもっと良くなる。

### 2. [Claude Code 作成者 Boris が公開した 13 の使用心法](https://mp.weixin.qq.com/s/TQ13vs9IPCtEM19k7b2f_Q)

1 人で、どうやってシリコンベースの軍団を指揮する？Boris の答え：**同時に 15～20 個の Claude インスタンスを実行**。ターミナルで 5 つのタブを開く、ブラウザでさらに 5～10 ページ開く、行ったり来たりしながら並行処理。

コア心法は 2 つ：**複利思考**——CLAUDE.md は 1 回限りのドキュメントじゃなく、チームが毎週内容を追加する知識ベース、毎回の code review で良くなっていく；**検証フィードバック**——Claude に仕事を検証する方法を与える、最終品質は 2～3 倍向上する。彼は Opus 4.5 + thinking モードだけを使う、理由はシンプル：1 回で正しくやる方が何度も修正するより速い。

### 4. [Claude Code LSP Tool に競合状態バグ、コミュニティが修正スクリプトを公開](https://linux.do/t/topic/1401997)

Claude Code ユーザーは注意。2.0.67 以降のバージョン（2.0.69 から最新の 2.0.76）にこの問題がある：**LSP Server プラグインが Enabled と表示されるが、実際には正しく読み込まれていない**、LSPManager は 0 Server を表示。

問題は設定ファイルの読み込み順序、initialize() 関数が空。コミュニティの大物がすでに修正スクリプトを書いた、acorn パーサーで対応する関数を見つけてパッチを当てる。スクリプトは --check チェック、--restore 復元、--fix-plugins プラグイン設定修正をサポート。
