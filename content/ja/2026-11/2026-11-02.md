### 1. Anthropic が Claude Code に他者のゲームの複製を禁止するルールを追加 🎮

**ゲームクローン規制が強化。** [Anthropic が Claude Code に他者のゲームの複製を禁止するルールを追加](https://www.36kr.com/p/4050722097828740)、**Anthropic** は Opus 5.5 のシステムプロンプトに制限を追加し、Claude が「他者の特定のゲームを再現すること」を拒否するよう誘導している。Opus 5.5 のリリース後、AI 支援によるゲームクローンのハードルが急低下し、インディーゲームの Demo が**一夜にして複製されるリスク**が生じていた。これは Anthropic による著作権保護への積極的介入であり、Claude Code でゲーム開発を行うチームは新たな境界線に注意が必要だ。

### 2. ブラジルの裁判所が文書にプロンプトインジェクションを隠した弁護士に罰金を科す ⚖️

**法廷文書への命令埋め込みが処罰された。** [JetStream Security の記事](https://jetstream.security/insights/brazilian-court-sanctions-prompt-injection-filing/)によると、ブラジルのパラー州の裁判所が、弁護士が訴訟資料に白文字・白背景でプロンプトインジェクションを隠した事件を処理した。裁判所システム Galileu が隠しコンテンツを検出し、AI ツールの審査プロセスへの干渉意図があると認定、**訴訟価額の 10%**、約**1.6 万ドル**相当の罰金が科された。これはおそらく法的文書へのプロンプトインジェクションに対する世界初の司法処罰であり、AI 支援の司法ツールの信頼性が制度によって逆に制約されつつある。

### 4. HackerBooks：HN コメントから 15,000 冊の本を掘り出したレコメンドサイト 📚

**HN コメントから本を掘り起こす、その規模は想像を超えている。** [HackerBooks](https://hackerbooks.org) は roansh が HackerTube にインスパイアされて制作し、主なデータパイプラインは Claude Opus 5.5 によって書かれた。About ページによると **15,362 冊**の書籍、270,334 件の言及が収録されており、56,456 名のコメンターから集められている。Sonnet 5.5 が各言及を推薦・中立・批判・無関係に分類し、Opus 5.5 との 400 件サンプルでの一致率は **85%** だった。これはモデル間の一致率であり、人手による正解率ではない。読書テーマで迷ったとき、直接トピック別のランキングを参照できる。

### 6. テックウィークリー：AI に社会的な関係を代理させてはいけない 🤔

**AI による社会的インタラクションの代行が混乱を生んでいる。** 阮一峰の[テック愛好者ウィークリー第 417 号](https://t.me/scitech_fans/420)は「AI に自分を代表させるな」をテーマに、AI にタピオカティーを注文させたり自動メール返信させたりすることが、相手に「あなたがそこにいる」という誤った認識を与えると指摘している。記事では **6 つの** AI モデルがそれぞれの人間の代わりにメールを送り合い、最終的に人間が一切関与しない循環会話が形成されたという実験を引用している。これは技術の問題ではなく、エージェンシーと信頼の境界の問題だ。AI の**自動返信**を多用しているユーザーにとって、改めて見直すべき示唆がある。

### 8. 復旦チーム：ハイブリッドアーキテクチャで全注意力にはどの効率的注意力を組み合わせるべきか 🔬

**スライディングウィンドウも線形も必要、ハイブリッドアーキテクチャに比較の根拠ができた。** 機器之心が[復旦チーム：ハイブリッドアーキテクチャで全注意力にはどの効率的注意力を組み合わせるべきか](https://mp.weixin.qq.com/s?__biz=MzA3MzI4MjgzMw==&mid=2651071440&idx=3&sn=ac0f863b4725bef4e45e4453d7e081e3)と報じ、復旦 MOSS チームの邱錫鵬氏らが論文「ハイブリッドアーキテクチャの長文力学」を発表した。全注意力とスライディングウィンドウ注意力（SWA）、ゲート付き線形注意力（**GLA/GDN**）をそれぞれ組み合わせた長コンテキスト性能を系統的に比較した結果、両者にはそれぞれ代替不可能な役割があり、どちらか一方だけを選ぶと相補性が失われるという結論が出た。長コンテキスト推論アーキテクチャを設計しているエンジニアは、この論文を選定の参考にできる。

### AiSOC はどんな種類のツールで、従来の SIEM とどう違うのか？

**AiSOC はセルフホスト可能なオープンソースの AI セキュリティオペレーションセンターで、LLM エージェントがアラート融合トリアージと MITRE ATT&CK 調査を担う。** [このプロジェクト](https://github.com/beenuar/AiSOC)はエージェントの各操作ステップに再生可能な意思決定台帳を提供しており、従来の SIEM がルールベースの相関分析を主体とし調査推論過程の完全な記録を欠くのとは対照的だ。MCP サーバーを内蔵し、Claude・Cursor・Continue との連携をサポートしている。
