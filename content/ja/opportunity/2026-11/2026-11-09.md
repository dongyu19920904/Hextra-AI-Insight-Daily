## 今日のメイン案件

### Claude Code を使っている開発者向け——認証情報が .claude ファイルと一緒にコミットされていないか確認する 🔍

**具体的なファイルパス・再現メカニズム・一次研究があり、今日一番取っ掛かりやすい出発点だ。** Apiiro は公開リポジトリで 1,122 件の `.claude/settings.local.json` に実際の認証情報が含まれているのを発見した。トリガーは「シークレットを含むコマンドを永久承認」した後、コマンドがファイルに書き込まれてコミットと一緒に公開されるという仕組みだ。

- **証拠と信頼性：** 中。[Apiiro 研究レポート：1,122 件の公開ファイルに認証情報が含まれることを証明した発見メカニズムとファイルパス](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again) に再現可能な排査パスがある。ギャップ：今回の候補インプットには影響を受けた開発者へのインタビューや有料意向の記録がなく、成約できるかはまだ検証が必要。
- **ターゲット層と地道な方法：** 未検証の仮説：Claude Code でコミットをプッシュしている個人開発者や小チームは、`settings.local.json` がリポジトリと一緒に公開されることを知らない可能性がある。今の地道な方法は、記憶に頼ってどのファイルが `.gitignore` に入っているか判断することかもしれない。
- **最小デリバリー：** 「Claude Code 認証情報漏洩セルフチェックパック」——①実行可能なセルフチェックスクリプト（`.claude/settings.local.json` の認証情報パターンをスキャン）；②修正チェックリスト（`.gitignore` 調整・コミット済みファイルの取り消し・漏洩疑いのある key のローテーション）；③説明ドキュメント（セキュリティ侵入テストと漏洩プラットフォームへの連絡は含まないと明記）。買い手は自分でスクリプトを走らせてチェックリストと照合できる。
- **48時間検証：** まずテストリポジトリで完全に一回走らせ、スクリプトが正しく識別できるか・失敗ポイントを記録（サンプル）。次にスクショを Claude Code を使っている開発者 3〜5 人に送り、直接聞く：「この問題知ってた？誰かが一通りチェックしてレポートを出してくれたら、いくら払う？」問い合わせが来るか、「自分のリポジトリも確認したい」という声があるか観察する。
- **初回案件と再購入：** テスト誘い文句：「Claude Code でコードをプッシュしたことある？.claude ファイルを一通り調べてレポート出すよ、30 分以内に納品。」初回案件の固定スコープ：指定リポジトリ 1 件のみ、結果レポートと修正チェックリスト付き、継続モニタリングと侵入テストは含まない。リピートは弱め、どちらかといえば一回限りの案件；「よくある漏洩パターンリスト」を素材として蓄積すれば、次回同種デリバリーのコストを下げられる。
- **リスクとやめ時：** コンプライアンスリスク中——スクリプトが認証情報の内容を読み取るため、買い手に「ローカルのみで実行、データはアップロードしない」と明示する必要がある。外部の人間がリポジトリに触れることを買い手が懸念する場合、信頼のハードルが転換率を妨げる。やめ時：ターゲットユーザー 5 人がサンプルを見て誰も問い合わせしない；テスト環境での誤検知率が高く信頼できる結論が出せない；または買い手が修正後の完全な安全性を保証するよう求めてくる（スコープ外、やめる）。
