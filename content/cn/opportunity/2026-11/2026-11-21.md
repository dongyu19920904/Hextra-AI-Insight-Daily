## 直接结论

- **直接答案：** 今天两个新项目值得用 48 小时测试：一个把代码库转成可查询知识图谱，另一个聚合多模型接入的网关工具。
- **做不做：** 先做 graphify，知识图谱结果更容易向买家展示；OmniRoute 作为备选小试。
- **先验证：** 用自己的一个真实代码库跑通 graphify，输出一份可展示的图谱样品，再拿样品问 3-5 个在用 Claude Code 或 Cursor 的开发者有没有付钱意愿。
- **何时停：** 跑通失败、图谱无法向买家解释清楚，或 5 位开发者全部没有意向。

## 今日主推

### 验证「把代码库转成可查询知识图谱」有没有开发者愿意付费

**交付的是可展示的本地图谱文件，不是教程。** graphify 今天出现在 GitHub，仓库说明显示它能把代码库、SQL schema、配置文件和 PDF 解析成本地知识图谱，支持 Claude Code、Cursor、Codex、Gemini CLI 的 `/graphify` 技能调用，每条边有说明，无需向量存储。

- **证据与可信度：** 中。[graphify 仓库：证明项目存在及代码库转知识图谱功能说明](https://github.com/Graphify-Labs/graphify) 为原项目一手来源，可直接核验。缺口：本次候选输入未提供实际运行截图、任何用户反馈或许可全文细节；需自行核对 MIT 二次分发和商标条款。
- **鱼塘与笨办法：** 待验证假设：接手旧项目的独立开发者，可能正在手动翻代码或靠注释猜关系；如果代码库超过几千行，这个动作可能每次都要重复。是否痛到愿意付钱，需要访谈确认。
- **最小交付：** 商品名：「项目知识图谱生成包」。交付内容：① 对买家的真实代码库跑一次完整解析；② 输出一份可在浏览器或工具里查询的图谱文件；③ 附说明文档（哪些文件类型被解析、哪些不在范围内）；④ 不含后续维护、模型接入配置或代码重构建议。买家可检查：能否在图谱上查到关键函数调用关系，边是否有说明文字。
- **48小时验证：** 先用自己 500-2000 行的代码库跑通完整解析，记录实际耗时和失败点。再把图谱截图或导出文件发给 3-5 个在用 Claude Code 或 Cursor 的开发者，直接问：「接手旧项目时会想要这个吗，愿意为这份图谱付多少？」观察是否有人追问交付方式或给出具体金额。
- **第一单与复购：** 测试邀约句：「你的项目我帮跑一遍，给你一份可以直接问 Claude 的知识图谱，限定 50 个文件以内。」第一单：单一代码库、文件数上限自定（建议先限 50 个），只含 AST 解析结果和说明文档，不含部署或 CI 集成。若跑通后流程可复用，复购方向为大版本迭代后重新解析，或扩展到 SQL schema + 文档联合图谱。
- **风险与停止：** 售后/合规风险低，本地解析不上传代码；需自行核对 MIT 二次分发和商标限制。停止条件：解析在目标代码库上无法复现、输出图谱无法被非作者理解、询问 5 位开发者后无人给出具体意向。

## 本周小试

### 验证「多模型网关接入包」对同时调用多个 AI 工具的开发者有没有付费意愿

- **证据来源：** [OmniRoute 仓库：证明项目存在及多模型单一端点网关功能说明](https://github.com/cheaper-inference/OmniRoute)
- **目标鱼塘：** 待验证假设：同时在用 Claude Code、Codex、Cursor 等多个工具、若需要在不同项目间手动配置接入的独立开发者，可能愿意为「一次跑通、统一端点」的配置结果付费。
- **最小交付：** 在测试环境完整部署 OmniRoute，接通至少两个模型提供商，输出一份可展示的配置截图和接入说明；买家可检查：能否通过单一端点正常调用两个以上模型。
- **48小时验证：** 先自己跑通部署，记录实际耗时和失败点。再把配置截图发给 3-5 个在用多模型工具的开发者，问：「你现在怎么管多个接入，这个能帮你省时间吗，愿意为跑通配置付钱吗？」观察是否有人描述当前切换痛点或询问具体范围。
- **为什么只是小试：** OmniRoute 售后/合规风险标注为中，仓库摘要中「150+ 免费」等表述需自行核查各提供商条款；付费意愿和合规边界均待验证，不宜直接进入成交。
- **停止条件：** 部署在干净环境无法复现、许可或提供商条款存在无法绕开的商用限制、5 位开发者均无意向。
