## 今日主推

### 给用了 Claude Code 的开发者查凭据有没有随 .claude 文件提交出去

**有具体文件路径、可复现机制和原始研究，是今天最有抓手的起点。** Apiiro 在公开仓库中发现 1,122 份 `.claude/settings.local.json` 含真实凭据，触发机制是「永久批准含密命令」后命令写入文件再随提交公开。

- **证据与可信度：** 中。[Apiiro 研究报告：证明 1,122 份公开文件含凭据的发现机制与文件路径](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again) 提供可复现排查路径。缺口：本次候选输入未提供受影响开发者的访谈或付费意向记录，能否成单仍需验证。
- **鱼塘与笨办法：** 待验证假设：正在用 Claude Code 推提交的独立开发者或小团队，可能不知道 `settings.local.json` 会随仓库公开，现有笨办法可能是靠记忆判断哪些文件进了 `.gitignore`。
- **最小交付：** 「Claude Code 凭据泄露自查包」——①可执行自查脚本（扫描 `.claude/settings.local.json` 中的凭据模式）；②修复清单（调整 `.gitignore`、撤销已提交文件、轮换疑似泄露的 key）；③说明文档（写清不包含安全渗透测试和联系泄露平台）。买家可自己跑脚本、对照清单核查。
- **48小时验证：** 先在测试仓库完整跑一次、记录脚本能否正确识别和失败点（样品）。再把截图发给 3-5 个用 Claude Code 的开发者，直接问：「这个问题你知道吗？有人帮你查一遍出报告，你会付多少？」观察是否有人询价或说「我想确认自己的仓库」。
- **第一单与复购：** 测试邀约：「你用 Claude Code 推过代码吗？我帮你查一遍 .claude 文件，出报告，30 分钟内交付。」第一单固定范围：仅查一个指定仓库，出结果报告和修复清单，不含后续监控和渗透测试。复购较弱，更像一次性单；可把「常见泄露模式清单」沉淀为分发素材，降低下次同类交付成本。
- **风险与停止：** 合规风险中——脚本涉及读取凭据内容，需明确告知买家「仅本地运行，不上传数据」。若买家对外部人员接触仓库有顾虑，信任门槛会卡住转化。停止条件：5 位目标用户看过样品无人询价；测试环境误报率高无法给出可信结论；或买家要求承诺修复后绝对安全（超出范围，停）。

## 本周小试

### 验证 llama-modchip 64GB 本地部署跑通包有没有人要

- **证据来源：** [llama-modchip 官方仓库：证明项目代码、量化参数和 64GB 内存需求说明存在](https://github.com/synchopate/llama-modchip)
- **目标鱼塘：** 待验证假设：有 64GB 内存设备、看过相关讨论但没跑起来的开发者。
- **最小交付：** 在自己机器完整跑一次，截图记录成功输出和实际速度；制作含量化步骤、实际 token/s 和踩坑记录的跑通说明。买家可对照文档自行复现，验收标准是能跑出第一个推理输出。
- **48小时验证：** 先跑通截图（样品），发给 3-5 个有 64GB 设备的开发者，问「这份跑通记录有用吗？愿意为省折腾时间付费吗？」观察有效询问数。
- **为什么只是小试：** 64GB 硬件门槛筛掉大多数人；README 速度和量化指标仅来自项目自述，需自己复现确认；`developer-tool-setup` 交付类型近 7 天已密集出现。
- **停止条件：** 自己跑不通；实际速度与 README 差距明显；或 5 位目标用户都没有 64GB 设备。
