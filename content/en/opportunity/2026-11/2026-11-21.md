## Bottom Line Up Front

- **Direct answer:** Two new projects today are worth 48 hours of testing: one turns a codebase into a queryable knowledge graph, the other is a gateway tool that aggregates access to multiple AI models.
- **Do it or not:** Start with graphify — knowledge graph results are easier to demonstrate to buyers. Try OmniRoute as a secondary option.
- **Validate first:** Run graphify on one of your own real codebases, produce a shareable graph sample, then show that sample to 3–5 developers who use Claude Code or Cursor and ask whether they'd pay for it.
- **When to stop:** If the run fails, if you can't explain the graph clearly to a buyer, or if none of the five developers express interest.

---

## Today's Main Pick

### Validate Whether Developers Will Pay to Turn a Codebase into a Queryable Knowledge Graph

**What you're delivering is a shareable local graph file, not a tutorial.** graphify appeared on GitHub today. The repository description states that it parses codebases, SQL schemas, configuration files, and PDFs into a local knowledge graph, supports `/graphify` skill calls in Claude Code, Cursor, Codex, and Gemini CLI, includes a description on each edge, and requires no vector storage.

- **Evidence and confidence:** Medium. [The graphify repository — confirms the project exists and describes the codebase-to-knowledge-graph feature](https://github.com/Graphify-Labs/graphify) is the primary source and can be verified directly. Gaps: the input reviewed for this candidate included no actual run screenshots, user feedback, or full license text; verify the MIT redistribution and trademark terms yourself.
- **Target audience and manual equivalent:** Unverified assumption — independent developers inheriting legacy projects may currently browse code manually or infer relationships from comments. If the codebase exceeds a few thousand lines, this effort likely repeats every time. Whether the pain is enough to justify payment needs to be confirmed through interviews.
- **Minimum deliverable:** Product name: "Project Knowledge Graph Generation Package." Deliverables: ① a full parse run on the buyer's real codebase; ② a graph file the buyer can query in a browser or tool; ③ documentation noting which file types were parsed and which are out of scope; ④ no post-delivery maintenance, model integration configuration, or code refactoring advice. The buyer can verify: whether key function call relationships are findable in the graph, and whether the edges carry descriptive labels.
- **48-hour validation:** First, run a complete parse on your own codebase of 500–2,000 lines and log the actual time taken and any failure points. Then send screenshots or the exported graph file to 3–5 developers who use Claude Code or Cursor and ask directly: "Would you want this when taking over a legacy project, and how much would you pay for this graph?" Watch for anyone who follows up about delivery details or names a specific price.
- **First sale and repeat business:** Test pitch: "I'll run your project through the tool and give you a knowledge graph you can query directly in Claude — limited to 50 files." First sale: single codebase, file count capped at whatever you decide (50 is a reasonable starting limit), containing only AST parse results and documentation, no deployment or CI integration. If the workflow proves repeatable, repeat business could come from re-parsing after major version updates, or expanding to a combined SQL schema and documentation graph.
- **Risks and stop conditions:** Post-sale and compliance risk is low — local parsing does not upload code. Verify the MIT redistribution and trademark restrictions yourself. Stop if: the parse cannot be reproduced on the target codebase, the output graph cannot be understood by someone other than its author, or none of the five developers you query express a concrete interest.

## This Week's Secondary Test

### Validate Whether Developers Who Call Multiple AI Tools Simultaneously Will Pay for a Multi-Model Gateway Setup

- **Evidence source:** [The OmniRoute repository — confirms the project exists and describes the multi-model single-endpoint gateway feature](https://github.com/cheaper-inference/OmniRoute)
- **Target audience:** Unverified assumption — independent developers simultaneously using Claude Code, Codex, Cursor, and similar tools, who must configure each integration manually across different projects, may be willing to pay for a "run it once, single endpoint" configuration result.
- **Minimum deliverable:** Deploy OmniRoute fully in a test environment, connect at least two model providers, and produce a shareable screenshot of the configuration and an integration guide. The buyer can verify: whether two or more models can be called normally through a single endpoint.
- **48-hour validation:** Run the deployment yourself first and log the actual time and failure points. Then send the configuration screenshot to 3–5 developers who use multiple AI models and ask: "How do you currently manage multiple integrations — would this save you time, and would you pay for a working configuration?" Watch for anyone who describes their current switching pain or asks about the specific scope of work.
- **Why this is only a secondary test:** OmniRoute's post-sale and compliance risk is rated medium. Claims in the repository summary such as "150+ free" need to be verified against each provider's terms. Both payment willingness and compliance boundaries remain unvalidated, so moving directly to a sale is premature.
- **Stop conditions:** Deployment cannot be reproduced in a clean environment, the license or provider terms contain commercial restrictions that cannot be worked around, or none of the five developers express interest.
