## 今日主推

### 验证「把已登录浏览器状态接进 AI 自动化流程」有没有人要

**ego-lite 的真正卡点不是功能，而是有没有人愿意为这个接入结果付费——这是待验证假设，不是已确认需求。**

项目声称零成本、零配置，让 Codex 或 Claude Code 直接复用你已登录的浏览器状态。对于每次跑自动化任务都卡在登录维护这一步的人，这个接入动作是个真实卡点。但愿不愿意外包这一步、愿意付多少，本次候选输入未提供任何访谈或询价记录。

- **证据与可信度：** 中。[ego-lite 官方仓库：证明项目存在、功能说明及零配置定位](https://github.com/citrolabs/ego-lite) 可直接核验代码与 README。缺口：本次候选未提供用户反馈或付费意愿记录；项目是否在主流系统上稳定复现尚无实测数据。

- **鱼塘与笨办法：** 待验证假设——可能是每天跑重复网页操作的独立开发者或小团队，目前可能在用 Playwright 手动维护 cookies，或每次任务都要重走登录流程。是否真的为此烦恼、是否愿意外包，需要访谈才能确认。

- **最小交付：** 在本地测试环境完成一次端到端流程：启动已登录浏览器 → 共享状态给 Claude Code → 执行一个具体网页任务 → 输出结果文件。交付物是复现记录 + 失败点说明 + 不包含项清单（不含目标网站账号维护、不含任务脚本定制、不含长期运维）。

- **48小时验证：** 先自己跑通一次并**记录实际耗时与卡点**；跑通后找 3-5 个有真实网页自动化需求的开发者，描述具体结果（「我帮你把已登录浏览器接进 Claude Code，你给我看你现在手动跑的那个流程」），问他们愿不愿意为跑通这一步出意向金。不跑通就不询价。

- **第一单与复购：** 第一单固定范围：指定一个网页任务场景，完成一次 ego-lite + Claude Code 端到端接入，交付复现步骤、结果截图和明确不包含项（不含账号安全保障、不含持续运维、不含多平台适配）。复购可能性低，更像一次性配置单；如果同一用户有多个重复场景，可沉淀成场景模板降低下次交付成本，但这取决于访谈结果，现在不预设。

- **风险与停止：** 风险中。浏览器登录状态共享涉及账号安全边界，目标网站服务条款可能限制自动化行为，复现前须核查合规边界。**停止条件**：本地复现失败且问题在许可或反爬层面无法绕过；或 5 位目标用户无一愿意出意向金；或发现目标用户自己已跑通不需要外包。
