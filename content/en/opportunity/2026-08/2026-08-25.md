## 直接结论
- **直接答案：** 今天先验证“把一个终端任务跑成可检查结果”的小交付；Claude Code 有原项目可核验，求职材料样品放到本周小试。
- **做不做：** 做一个单任务样品，但把付费需求当作待验证假设，不先做大而全工具包。
- **先验证：** 先跑通真实样例，再给 3-5 位目标用户查看，观察是否追问范围、询价或提出试用。
- **何时停：** 无法复现、许可条件说不清，或 5 位目标用户都不询价、不试用，就停止扩展。

## 今日主推
### 给需要重复处理代码库任务的小团队交付可检查的终端工作流样品
**先卖一个能验收的结果，不先卖 Claude Code 教程。** 今天的信号是，Claude Code 原项目公开说明它能理解代码库、执行日常任务并处理 git 工作流；这足以做样品，但不足以证明有人愿意付费。

- **证据与可信度：** 中。[Claude Code 官方仓库：证明该终端代理编码工具及其公开功能说明存在](https://github.com/anthropics/claude-code)。本次候选输入未提供独立实测、买家询价或付费记录；具体任务的稳定性和许可边界仍需核对。
- **鱼塘与笨办法：** 待验证假设：需要反复整理代码、解释变更或处理固定 git 任务的小团队，可能仍在手工复制命令、逐段检查结果。先只验证一个任务，不把对象扩大成所有开发者。
- **最小交付：** 商品雏形叫“单任务终端工作流样品”，包含：一份可运行配置、一组输入字段、一份输出检查清单、一个脱敏前后对比样例。验收是买家能按约定输入得到指定格式结果并逐项检查；不包含全项目改造、长期维护和无限次调整。
- **48小时验证：** 先用非敏感代码库跑通一个固定任务，记录实际耗时、成本、失败点和输出差异；再把样品给 3-5 位相关用户查看，观察是否提出真实任务、询问交付范围、要求试用或表达意向。
- **第一单与复购：** 测试邀约句：“我把你的一个重复代码库任务跑成可检查样品，先看结果再决定是否继续。”第一单固定为一个任务、一次配置和一个验收样例，不包含其他任务迁移、账号代配或长期稳定承诺。若同类任务持续出现，可沉淀检查清单、组件和案例做标准交付；否则更像一次性单。
- **风险与停止：** 中：项目可核验，但本次候选输入未提供完整许可、依赖和内容边界的独立核对，且样品可能受代码库差异影响。若无法复现、实际耗时超过买家可接受范围、许可条件无法确认，或 5 位目标用户都无询价或试用意愿，停止做大。

## 本周小试
### 给求职者交付一份可逐项检查的单岗位材料样品
- **证据来源：** [ai-job-search 原项目仓库：证明一个基于 Claude Code 的求职应用框架公开存在，并展示岗位评估、简历、求职信和面试准备场景](https://github.com/MadsLorentzen/ai-job-search)
- **目标鱼塘：** 待验证假设：正在投递具体岗位的求职者，可能愿意先查看一份单岗位材料样品；本次候选输入未提供其付费行为、中文场景反馈或痛点频率。
- **最小交付：** 用公开岗位和虚构经历做一份样品，包含岗位要求拆解、简历匹配缺口、求职信初稿和 5 个面试问题；买家可逐项对照检查，不承诺录用结果。
- **48小时验证：** 先跑出一份脱敏样品，再给 3-5 位正在投递的人查看，观察他们是否指出具体修改项、询问范围、提出试用或表达意向。
- **为什么只是小试：** 项目说明与展示结果较清楚，但本次候选输入未提供中文求职实测、独立复现记录或付费证据；先验证单岗位结果，不做平台化包装。
- **停止条件：** 样品无法让目标用户指出具体修改价值，或 5 位用户都不愿提供岗位信息、不询价、不试用，就停止投入。
