### 8. musl + OpenSSH Legacy Compatibility Logic Combined Creates a Password Authentication Vulnerability

**Password authentication can be bypassed under a specific combination of conditions.** Security researcher Özgün Kültekin's [vulnerability analysis published on sshhole.com](https://sshhole.com) traces the exploit chain: **musl**'s crypt() return value, OpenSSH's salt-borrowing logic, and the account field align under specific conditions, allowing an overlong password to pass authentication incorrectly. Triggering the vulnerability requires all three conditions simultaneously: **musl + non-PAM sshd + password authentication enabled**, with the target account field set to `*`. OpenSSH 10.6p2 has patched this; disabling password authentication also mitigates it. Ops teams running Alpine or embedded musl devices should verify their versions as a priority.

![musl + OpenSSH legacy compatibility logic combined creates a password authentication vulnerability · Original illustration](https://sshhole.com/receipts/3bsd-passwd.png "musl + OpenSSH legacy compatibility logic combined creates a password authentication vulnerability · Original illustration")
