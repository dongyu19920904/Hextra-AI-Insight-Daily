### 4. AI Tools Are Turning 40 Years of Software Security Debt Into Active Attack Paths

**Vulnerabilities are found faster; fixes are still slow.** IEEE Spectrum [reports on this asymmetry using PHP2Shell as a case study](https://spectrum.ieee.org/ai-in-cybersecurity-php2shell-vulnerability): AI-assisted auditing found an **exploitable** code-execution path in roughly two weeks, while four engineers spent about two months developing a patch 🔒. ### 7. Laptop Runs Qwen 27B Locally to Identify Game Neural Network Weights

**A local 17 GB model completes a weight-interpretation task.** Simon Willison [documents this experiment on his blog](https://simonwillison.net/2026/Nov/3/qwen-can-interpret-model-weights/): running Qwen 3.8 27B through LM Studio, he fed the model floating-point weights and architecture descriptions from a small game's policy network and asked it to guess what game the network was trained to play. ### 8. RTX Spark Laptop on Linux Drops to 21% of Windows Inference Speed When Plugged In

**Plugging in the charger actually tanks performance.** MindStudio benchmarked the MSI Prestige RTX Spark's [inference performance on native Linux](https://www.mindstudio.ai/blog/linux-nvidia-rtx-spark-laptop): when plugged in, GPU frequency stalls at around 780 MHz versus roughly 2.2 GHz on Windows; GPT-OSS-120B throughput is 65.4 tokens/s on Windows, versus only **13.9 tokens/s** on native Linux while plugged in. Unplugged, Linux reaches approximately 61–67 tokens/s. The author attributes this to a Windows-exclusive encrypted power table and currently recommends using WSL to retain Windows-side power management. Linux users planning to run **local inference** on RTX Spark should treat WSL as the more reliable path for now.

### Fake Job Interviews Plus Internal AI Tools: The Attack Chain Behind the $6.3 Billion Binance Heist

**Social engineering + internal access + AI tools form a rare attack chain.** The Register reconstructs the incident based on [Binance's preliminary incident report from November 3](https://www.theregister.com/security/2026/11/03/north-korean-fake-job-interview-led-to-63b-binance-heist/5307398): attackers first used malicious developer tools to map internal relationships, then used a recruitment video interview as a pretext to get an engineer to run a malicious repository; they then used the compromised device and internal AI tools to laterally obtain access credentials for two more engineers, ultimately completing the theft via a container deployment token. The attack unfolded from June through October and involved **$6.3 billion** 🔒. Binance says it has rebuilt the affected systems and that the investigation is ongoing. For enterprise security teams, this attack chain illustrates that the permission boundaries of internal AI tools need to be included in access audits alongside code repositories and deployment tokens.
